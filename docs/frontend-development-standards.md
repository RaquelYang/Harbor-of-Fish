# 前端開發規範

本文件適用於規劃中的 Angular 21 公開網站及後續管理介面。開發者與 AI agent **必須**同時遵守[共同開發規範](development-standards.md)的 TDD、API 契約、資料語意及交付要求。[八階段開發計畫](development-plan.md)的第一階段僅建立本機測試頁與 API 往返；管理介面不在八階段交付範圍內。

## 元件與狀態

- 前端**必須**依功能或領域組織程式碼。頁面元件組合使用者流程與領域元件；較小元件負責界定清楚的呈現或互動。元件的輸入、輸出及狀態來源**必須**明確，狀態放在實際擁有它的頁面、功能或服務，避免多處複製同一份可變狀態。
- API 呼叫**必須**集中於具型別的存取層，不得在頁面或呈現元件散佈未型別的 HTTP 呼叫。前端只透過 API 取得資料，**不得**直接連線 PostgreSQL。
- 共用元件**不得**依賴特定頁面的業務資料或路由假設。只有實際重用或能降低已出現的複雜度時才抽成共用元件；若需要大量條件參數才能共用，先保留局部實作。
- 模板**不得**承載多步驟領域規則或資料轉換。將行為放在具名、可測試的元件邏輯或功能服務，模板只表達狀態與呈現關係。

## 使用者介面與資料呈現

- 互動介面**必須**可在手機尺寸使用，支援鍵盤操作、可辨識的標籤、焦點與選取狀態。地圖等非標準控制須提供可操作的替代方式；地圖與列表選取狀態須一致。
- 非同步畫面**必須**依情境處理載入、失敗、空結果與未知／資料待補狀態。未知不得靜默轉成空集合、零值或否定事實；錯誤訊息須可理解，並在適用時提供重試、返回或清除篩選等操作。
- 漁季、價格與洋流內容**必須**保留[共同規範](development-standards.md)定義的來源及限制資訊。畫面不得把代表性漁季說成實際月別漁獲、把批發價格說成零售價格，或把科普示意說成即時觀測。
- 地點探索功能的定位權限只可在使用者主動操作時請求。拒絕或無法定位時，手動搜尋與縣市篩選仍須可用；公開瀏覽不得以登入或管理介面作為前置條件。第一階段本機測試頁不提供定位或地圖。

## 前端 TDD 驗收邊界

- 依[共同 TDD 流程](development-standards.md#tdd-與測試要求)先確認使用者可觀察的介面與行為，再寫失敗測試。測試**必須**驗證實際輸入、操作及畫面狀態，例如地圖／列表同步、篩選、搜尋、定位拒絕、空結果及未知資料；功能未觸及的情境不需為清單本身製造測試。
- API 回應呈現測試**必須**涵蓋該功能的成功、錯誤及缺值語意。測試從使用者可見的結果觀察，不依賴元件私有方法或內部呼叫次數。跨前後端的主要流程依共同規範與產品階段安排端到端驗收。
- 目前尚無前端骨架或測試工具；建立骨架後，**必須**在本規範記錄已實際執行的安裝、啟動、測試、lint、build 命令及瀏覽器驗收結果，或直接連到 repository 根目錄 `README.md` 中對應的實測紀錄。每項證據須可查到執行目錄、依賴服務、實際 Node 版本、命令、結果及瀏覽器測試資料來源；未執行者標「待驗證」。跨端冒煙與重啟的總結果記於根目錄 `README.md`。
