# API 與領域模型

本文件描述 API 與領域的方向性契約，不指定實際 DTO、資料表或固定欄位清單。具體資源表示方式應由實作依使用情境再定義。

## API 版本與路徑方向

HTTP API 使用 `/api/v1` 作為版本前綴。相容性調整留在既有版本；無法相容的契約變更以新版本規劃。公開查詢與管理操作在路徑及授權政策上清楚區分：

- **公開查詢**：提供已發布魚類及漁港內容的讀取端點，例如 `/api/v1/fish`、`/api/v1/fish/{id}`、`/api/v1/ports` 及 `/api/v1/ports/{id}`。端點支援的篩選、排序與分頁依實際需求決定。
- **管理 CRUD**：在 `/api/v1/admin` 下提供魚類、漁港及漁業文化內容的建立、讀取、更新與刪除操作，並提供發布或下架等狀態轉換。資源路徑與公開資源可對應，但管理端點永遠要求管理權限。
- **漁業文化內容**：依內容需求提供公開讀取，並由管理端建立、更新及控制發布狀態。內容可連結相關魚類、漁港或兩者；呈現及查詢方式不預設為單一頁面或固定路由。

以上路徑是資源命名方向，不是已實作端點清單。所有讀寫行為仍由後端驗證及授權。

## 發布狀態與公開界線

內容至少需要區分尚未公開與已公開狀態。管理者可檢視及編輯尚未公開的內容，也可執行發布與下架操作；一般公開查詢只能取得已發布且符合公開條件的內容。未發布內容、管理草稿及管理中繼資料不得因前端隱藏連結而暴露，後端必須在每個公開查詢路徑落實篩選。

刪除是管理端受控操作。若內容已被其他領域資料引用，實作應定義避免破壞關聯的處理方式，例如限制刪除、先解除關聯或採用下架；具體策略待領域需求確認。發布及下架是有權限的狀態轉換，不應視為一般訪客可執行的更新。

## 管理端認證與授權

Spring Security 保護所有管理端點。後端須驗證管理者身分，並授權其執行管理 CRUD 與發布相關操作。認證提供者、登入流程、管理角色細分及憑證生命週期尚待決策；這些決定不得改變「伺服器端授權為準」的邊界。前端隱藏管理功能或保護管理路由不能取代 API 的認證與授權。

目前範圍不包含一般會員帳號、一般訪客登入、會員個人資料或會員角色。公開瀏覽不要求建立會員身分。

## 核心領域關係

- **魚類**描述可供查詢的魚種內容。它可與漁港及漁業文化內容建立有意義的關聯；是否提供特定魚種的產地、季節或俗名等資訊，由內容需求決定。
- **漁港**描述港口及其相關介紹。漁港可關聯在該地具有代表性的魚類或漁業文化內容；關聯的基數及維護方式不在此固定。
- **漁業文化**以可閱讀的內容記錄地方知識、活動、技藝或故事。文化內容可引用一種或多種魚類、漁港，亦可不關聯特定魚種或港口。
- **發布狀態**適用於可公開呈現的內容，控制該內容是否進入公開查詢結果。管理端仍可在授權後檢視未發布內容。

這些關係表達領域概念，不要求特定資料表設計。實作可依查詢與維護需求選擇直接關聯、關聯資源或其他持久化方式，同時維持公開與管理存取界線。
