# Harbor of Fish 手機版網站產品規劃

## 產品定位

Harbor of Fish 是以手機為優先的漁港與當季魚資訊網站。主要讀者是想吃當季魚的人；他們可能想知道附近或指定縣市有哪些漁港、某個月份有哪些有可靠資料支持的魚種，以及市場批發價格如何變化。公開產品的首頁優先提供漁港地圖，讓使用者先從地點探索，再讀取港口與魚種內容。

本文件描述產品功能方向；實際交付依[八階段開發計畫](development-plan.md)。其第一階段只建立本機測試骨架，不提供地圖或真實領域內容。下文原先的三個功能群組分別由八階段計畫的第二至四、第五至六、第七至八階段交付，不再用作交付階段編號。

產品採實用查詢工具風格：地圖、篩選、搜尋和精簡資訊卡先呈現，解說內容依需要展開。資料來源、適用期間、資料缺漏與資訊類型要清楚標示。代表性漁季不能表述成每月實際漁獲；批發行情不能當成零售價格；科普洋流圖不能當成即時海況或漁獲預測。

## 已確認的產品選擇

- 主要讀者：想吃當季魚的人。
- 公開產品首頁優先漁港地圖，整體採實用查詢工具風格；地圖由八階段計畫的第三階段交付。
- 地點與內容功能納入全臺漁港基本資料，並從北、中、南、東、離島各選一個港口製作深度內容；另選約十二種野生海魚作為魚種內容首批範圍，分別在第二至四階段準備與交付。
- 地圖可依縣市與月份篩選，也可搜尋港口或魚種；月份篩選依有來源佐證的代表性漁季內容呈現，不推論實際月別漁獲。
- 使用者只有點選定位功能時，才向瀏覽器請求位置權限；拒絕或無法定位時仍可手動選縣市和搜尋。
- 價格與趨勢功能查證後呈現魚種批發市場月價格趨勢；預設範圍依資料來源可用性確認，並可切換有可用資料的市場。
- 洋流故事功能提供手機可滑動的互動故事卡，連結港口與魚種，明確標示為科普示意。

港口與魚種尚未指定名稱。首批選擇依區域代表性、可靠資料來源、可佐證程度及合適素材是否可取得決定，不先把任何候選名稱當成已確認內容。

## 手機首頁與典型操作

首頁以全臺地圖為主視覺，地圖可切換為漁港列表或在小螢幕以地圖、列表分區呈現。頂部或地圖上方提供縣市、月份篩選和搜尋；定位按鈕由使用者主動點選。選取漁港後，畫面底部顯示可展開的資訊卡，摘要港口名稱、所在縣市、資料狀態及深度內容入口。地圖標記和列表項目保持選取狀態同步，篩選條件可清除或調整。

典型路徑：

1. 使用者開啟首頁，先瀏覽全臺漁港分布，或手動選擇縣市與月份。
2. 使用者可輸入港口或魚種名稱搜尋；若要看附近港口，再點定位並自行決定是否授權。
3. 使用者點地圖標記或列表項目，從底部資訊卡查看港口摘要及有來源支持的魚種／漁季內容。
4. 進入魚種內容後，查看代表性漁季、資料來源及其限制；價格與趨勢功能完成後再查看批發月價，洋流故事功能完成後再探索科普故事卡。

縣市、月份及搜尋條件一起使用時，介面必須明確呈現目前條件。若某港口的月份資料未知，不能把未知當成「該月沒有魚」；畫面需以「資料待補／尚無可用資料」等中性狀態，區別「有資料佐證該月屬代表性漁季」與「目前沒有足夠資料判定」。產品不宣稱掌握完整月別漁獲。

## 產品功能群組與驗收方向

### 地點探索與基礎內容（交付階段二至四）

**功能範圍**

- 建立全臺漁港基本資料與可操作的手機地圖、列表檢視、縣市篩選、月份篩選、港口／魚種搜尋及按需定位。
- 點選港口後顯示底部資訊卡。先完成北、中、南、東、離島各一個深度港口內容，以及約十二種野生海魚的首批內容。
- 港口深度內容和魚種內容要標出資料來源、代表性漁季的涵義及尚未有資料的項目。月份篩選只依已查證的代表性漁季關聯提供探索，不可將其包裝成實際月別漁獲資料。
- 對沒有月份／魚種資料的港口保留「未知／待補」狀態，不以空集合或未建立關聯推導「無魚」。若篩選結果不包含資料未知的港口，介面要交代這是資料尚未確認，不能讓使用者誤讀成該港口當月沒有魚。

**資料流**

1. 維護者從候選政府資料來源取得漁港名稱、位置及縣市等基本資訊，檢查座標、欄位、涵蓋範圍、更新日期、授權和可重複取得性。
2. 開發者以人工查證方式補充五區代表性深度港口、魚種、港口關聯、代表性漁季、文字與素材來源；每筆內容保留來源與查證狀態。初期資料由開發者維護，不假設存在管理介面或自動匯入管線。
3. 後端持久化於 PostgreSQL，結構變更由 Flyway 管理；Angular 手機前端呼叫 Spring Boot 模組化單體的版本化 REST 公開讀取 API `/api/v1`。瀏覽器不直接連資料庫。公開 API 只回傳可公開的內容。
4. 前端依 API 資料呈現標記、列表、篩選、搜尋、定位結果和底部資訊卡；定位只在使用者點擊後向瀏覽器請求。

**完成條件**

- 全臺漁港基本資料已按來源可追溯地匯整並檢視位置、縣市及欄位品質；未確認的記錄標示待查，不虛構補值。
- 五個區域各完成一篇有可靠來源支持的深度港口內容，另完成約十二種野生海魚內容；名稱依查證及素材可得性選取。
- 手機上可切換／使用地圖與列表、依縣市和月份篩選、搜尋、選取港口並讀取底部資訊卡。月份篩選清楚區分已知與未知，不把缺資料顯示成無魚。
- 首次開啟網站不主動索取定位；點選定位時才詢問。拒絕授權仍可用手動搜尋和縣市篩選完成探索。
- 所有展示內容均可找到來源或明確的待查證標記，且不將代表性漁季描述為實際月別漁獲。

### 批發價格趨勢與當季探索建議（交付階段五至六）

**功能範圍**

- 以最近六十個完整月份為批發市場月價格資料的查證目標；來源不足時縮小並標明實際可用期間。只有來源公布且統計口徑清楚的整體月價可作預設，否則以資料完整的單一市場為預設；切換市場後清楚顯示範圍。
- 每張圖表或資料摘要標明價格單位、資料期間、來源、最後更新時間與缺值。沒有資料的月份不可補造成連續價格或暗示為零；不同單位或口徑未能合理比較時，不合併比較。
- 提供「當季探索建議」前每天檢查經核准來源的禁漁、保育及其他相關限制；只有來源與公告可可靠判讀，且至少三種魚種通過查核時才啟用。建議結合代表性漁季、批發價格趨勢及來源資料，以使用者看得懂的原因說明，並呈現資料限制，不把低批發價說成零售便宜或保證買得到。限制資料失效或公告無法解析時停止顯示建議。

**資料流**

1. 維護者查證漁業署候選批發行情資料可否按魚種、月份、市場取得，並確認歷史期間、單位、統計口徑、市場清單、更新頻率、授權及缺漏表示方式。
2. 維護者另行查找主管機關發布的禁漁期、保育物種和適用範圍資料；建立推薦規則前，確認規則可追溯且能先排除受限制情況。價格、代表性漁季及限制資料都須保留來源、涵蓋期間和更新資訊。
3. 初期經查證的資料由開發者維護並整理進 PostgreSQL；Flyway 管理 schema。價格來源的可重複取得性、授權與修訂方式確認後，才建立每月自動整理與官方修正記錄；本文件不固定資料表、DTO 或匯入方式。
4. Spring Boot `/api/v1` 公開讀取 API 提供已整理的趨勢及建議理由資料；Angular 顯示可核對來源的預設範圍、市場切換、來源和缺值狀態。建議邏輯先套用限制查核，再綜合漁季、價格與來源；不可由價格單獨決定。

**完成條件**

- 有可靠來源的魚種與市場資料涵蓋近五年可取得的月資料，並說明實際可用期間；若來源不涵蓋整五年，產品明確縮小並標示期間，不製造缺失月份。
- 預設趨勢及市場切換結果可核對來源；若來源沒有可用的整體月價，不自行平均冒稱整體。價格單位、期間、來源、更新時間和缺值狀態可在手機畫面辨識。
- 建議啟用前已查證禁漁／保育限制並排除不宜推薦項目；來源失效或公告無法判讀時保持關閉。每項建議能指出漁季、批發價格及來源如何影響理由，並說明不足或不確定之處。
- 使用者能辨別批發價格與零售售價、代表性漁季與實際月別漁獲；無資料不呈現為零價、無漁獲或保證可購買。

### 洋流互動故事卡（交付階段七至八）

**功能範圍**

- 製作適合手機直向滑動、逐卡閱讀的洋流科普互動故事，連結相關港口與魚種，讓使用者從地圖或魚種內容進入故事，再返回探索。
- 每個故事卡明確標示為科普示意，說明所用的資料與圖像來源、示意範圍及簡化之處。清楚聲明內容不是即時海流觀測、當下海況、港口周邊即時狀態或漁獲預測。
- 故事內容只採有可靠資料支持的海流概念與港口／魚種關聯；不能從洋流故事推導某港口現正有特定魚種或預測漁獲。

**資料流**

1. 編輯者以中央氣象署等候選科普來源查證洋流概念、適合的港口和魚種關聯，以及圖像或素材的授權與可用方式。
2. 開發者整理故事卡文案、科普示意圖及其來源／限制，和已完成的港口、魚種內容建立可追溯關聯，初期仍由開發者維護。
3. 內容保存於 PostgreSQL，schema 變更由 Flyway 管理；後端公開 API 提供已發布故事、港口及魚種關聯。Angular 以可滑動卡片呈現，從卡片導向相關港口或魚種頁面。

**完成條件**

- 手機可順暢閱讀並操作故事卡，文字、圖像和互動控制在窄螢幕可用，且故事卡能導向正確的港口與魚種內容。
- 洋流敘述和素材有可追溯來源；示意與真實觀測的差別在進入故事時及相關視覺呈現處都清楚可見。
- 故事沒有被呈現為即時海流、即時海況或漁獲預測，且不聲稱示意圖可代表特定日期或港口的實際狀態。

## 技術方向與範圍界線

- 前端採 Angular（現有架構文件預設 Angular 21）；後端採 Spring Boot 模組化單體，提供版本化 REST API `/api/v1`；資料庫採 PostgreSQL，schema 遷移採 Flyway。
- 第一版以匿名公開讀取為主。第一批內容由開發者維護；管理介面及其認證授權留待後續需求確認，不納入本次網站規劃的第一版交付。
- 前端只透過 API 取資料，不直接連 PostgreSQL。公開 API 僅提供可公開內容；管理寫入若未來加入，仍由後端授權控制。
- 本文件不固定 DTO、資料表、欄位、API 篩選參數或匯入實作，也不選定部署供應商、正式環境拓樸或資料管線。相關細節待查證資料來源與實際使用情境後再設計，並與架構文件同步。
- 本文件保留產品功能與資料語意；交付先後、第一階段測試骨架及首次公開閘門以[八階段開發計畫](development-plan.md)為準。這些描述不代表網站程式或真實資料已建立。

## 手機驗收情境

1. **初次瀏覽與定位**：在手機首次開啟網站不出現定位權限要求；點選定位後才由瀏覽器詢問。選擇拒絕後，仍可手動選縣市、搜尋港口及操作地圖／列表。
2. **地圖、列表與資訊卡**：選取一個漁港標記後，相同港口在列表中同步選取；底部資訊卡不遮住主要操作，能展開閱讀深度內容或返回地圖。
3. **縣市與月份篩選**：選擇縣市和月份後，結果符合已查證內容；月份未知的港口顯示待補或其他中性狀態，不被標成該月無魚。清除月份條件可回到縣市結果。
4. **搜尋與空結果**：搜尋港口或魚種可辨識結果；查無結果時顯示明確空狀態，篩選條件仍可檢視及清除。
5. **價格閱讀（交付階段五）**：窄螢幕圖表可讀取或以替代列表檢視；預設趨勢以來源可核對的範圍為準，市場切換後標示市場、單位、資料期間、來源、更新時間及缺值，不能把缺值畫成零。
6. **建議閱讀（交付階段六）**：魚種先通過禁漁／保育查核；理由能說明代表性漁季、批發價格及來源，不把批發行情說成零售價格或保證供貨。
