# 後端開發規範

本文件適用於規劃中的 Spring Boot 模組化單體及 PostgreSQL。開發者與 AI agent **必須**同時遵守[共同開發規範](development-standards.md)的 TDD、API 契約、資料語意及交付要求。管理端規則在後續管理功能實作時適用，不增加產品第一階段範圍。

## 領域模組與分層

- 後端**必須**依魚類、漁港、漁業文化等領域組織模組化單體。模組透過明確的應用介面協作，不得任意讀寫其他模組的內部資料或依賴其持久化實作；不得僅因模組數量而拆成微服務。
- Controller 負責 HTTP 協定轉換；應用服務協調使用案例與交易；領域程式維持業務規則及一致性；資料存取層封裝 PostgreSQL 查詢與映射。每層**必須**保有清楚責任，不把領域規則塞進 Controller 或資料存取類別。
- 請求與回應 DTO **不得**直接暴露資料庫實體或內部持久化欄位。交易邊界**必須**涵蓋一個一致的使用案例，由後端控制；不能依賴前端呼叫順序維持資料一致性。跨模組交易責任須在應用介面或使用案例中說明。
- 外部輸入**必須**在後端驗證，包含格式、必要欄位及領域不變條件。錯誤回應須一致且能供呼叫端判斷，不得包含堆疊追蹤、SQL、憑證或內部主機資訊。

## 公開資料、安全與遷移

- 公開 API **只能**回傳已發布且可公開的內容。管理草稿、中繼資料及憑證資訊不得因前端隱藏而被公開端點取得；資料缺漏也不得被當成否定事實。
- 管理操作開始實作後，每個操作都**必須**由 Spring Security 在後端驗證身分與權限。前端路由限制或按鈕隱藏只改善操作體驗，不構成安全控制。管理 CRUD、發布、下架及刪除僅在相應產品需求確立後實作。
- PostgreSQL schema 變更**必須**透過 Flyway 版本化遷移。遷移須可追溯、順序明確，並與程式版本及資料模型一併檢視；不得以手動資料庫操作代替納入版本控制的結構變更。
- 日誌須提供必要的診斷資訊，同時**不得**記錄密碼、存取權杖、完整憑證及不必要的敏感資料；必要欄位應遮蔽或去識別化，避免將使用者輸入原樣記錄為可執行內容。範例設定不得包含真實秘密。

## 後端 TDD 驗收邊界

- 依[共同 TDD 流程](development-standards.md#tdd-與測試要求)先確認公開介面與行為，再寫失敗測試。領域與應用測試**必須**驗證規則、狀態轉換、缺值語意及使用案例結果，不依賴內部方法切分。
- HTTP/API 測試**必須**涵蓋受影響端點的路徑、輸入驗證、回應、錯誤及發布界線；管理操作實作時另驗證未認證與無權限請求遭拒。對持久化、查詢、映射或 Flyway 的變更，**必須**驗證遷移可依實際流程套用，且重要資料能保存與讀取；不得假設替代資料庫行為等同 PostgreSQL。
- 目前尚無後端骨架或測試工具；建立骨架後，**必須**補上實際確認可執行的安裝、測試、lint、build、資料庫與遷移驗證命令，並註明執行目錄及必要服務。
